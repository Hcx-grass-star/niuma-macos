# 2026-11-04

## 打包与分发

- 新增 `scripts/package-release.sh`：构建 →（可选 Developer ID 签名 + 公证 + 装订）→ 组装 `dist/` → `ditto` 打 zip，内含 `.app` 与自动生成的「安装说明.txt」。
- 本机无代码签名证书（`security find-identity` 为 0），当前走 ad-hoc 临时签名；接收方需在「系统设置 → 隐私与安全性」点「仍要打开」，或 `xattr -dr com.apple.quarantine`。脚本已预留 `DEVELOPER_ID_APP` + `NOTARY_PROFILE` 环境变量走公证路径。
- 分发包命名 `牛马上班-<版本>-macOS-universal.zip`；`dist/` 已加入 `.gitignore`。

## 兼容性：最低 macOS 13 + 通用二进制

- `Package.swift` 的 `platforms` 与 `Resources/Info.plist` 的 `LSMinimumSystemVersion` 从 27.2 同步下调到 13.0（两处必须一致）。
- `scripts/build-app.sh` 改为 `swift build --arch arm64 --arch x86_64`，产出 fat 二进制；脚本用 `lipo -archs` 打印实际架构。
- 三处 macOS 14+ API 加回退：无参 `NSApp.activate()`、`NSRunningApplication.activate()`（旧系统用 `ignoringOtherApps`）、`NSViewController.loadViewIfNeeded()`（改为访问 `view`）。
- 版本下限的技术原因是 `SMAppService`（macOS 13+ 登录启动）。
- 验证：release 构建通过、8 组集成验证全过、arm64 切片在本机 macOS 27.2 正常启动、x86_64 切片经 Rosetta 可启动；macOS 13–26 与真实 Intel 硬件仍未实机验证。

## 环境注意

- 本机 SwiftPM 在受限环境下执行 manifest 编译会报 `sandbox-exec: sandbox_apply: Operation not permitted`，需 `swift build --disable-sandbox`；`build-app.sh` 已支持 `NIUMA_SWIFT_NO_SANDBOX=1` 开关。
- 手动运行二进制验证时会命中 `main.swift` 的单实例判断（已运行则静默 `exit(0)`）；测试前先 `pkill` 残留实例，否则会误判启动失败。

## Gatekeeper 拦截的实际表现

- 对方双击分发包会看到「未打开“牛马上班”／Apple 无法验证……恶意软件」，弹窗只有「完成」和「移到废纸篓」，没有「打开」。这是未公证应用的例行拦截，不是病毒报警。
- 正确路径：点「完成」→ 系统设置 → 隐私与安全性 → 「仍要打开」（该按钮仅在拦截后约一小时内可见）→ 再次双击确认；或直接 `xattr -dr com.apple.quarantine`。
- 已在 `package-release.sh` 生成的「安装说明.txt」中按此弹窗原文重写步骤，并明确警告不要点「移到废纸篓」。

## 图标

- 图标源为 `Resources/AppIcon.png`（1024×1024，image_gen 生成），`Resources/AppIcon.prompt.md` 记录提示词与转换流程。
- `build-app.sh` 会把 `Resources/AppIcon.icns` 装进应用包并计入 `NiumaSourceHash`；因此 `Resources/AppIcon.icns` 是必需产物，缺失会导致构建失败。
- icns 由 PNG 经 `sips` 生成 10 个尺寸 + `iconutil -c icns` 打包。
