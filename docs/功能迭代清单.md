# 牛马上班功能迭代清单

日期：2026-11-05
状态：分期实施中；第一期代码已实现，本次优先交付本月金额和菜单栏显示切换；验收边界以验证记录为准。

## 1. 规划目标

围绕“配置一次工资和作息，随时查看预估收入”的核心体验，先完善节假日和排班计算，再增加统计与日常体验。

本文承接已有的当前已赚、本年预估已赚和更新检查能力。已有能力及验证边界以 [需求文档](需求文档.md)、[README](../README.md) 和对应验证记录为准；本文中的待办不代表已经实现或验收通过。

## 2. 迭代总览

| 迭代 | 主题 | 主要交付 | 优先级 | 相对复杂度 |
| --- | --- | --- | --- | --- |
| 第一期 | 中国节假日与调休 | 全国统一节假日安排、补班识别、收入计算联动 | P0 | 中 |
| 第二期 | 排班例外 | 指定日期上班或休息、个人假期、临时加班、近期日历 | P1 | 中 |
| 第三期 | 收入统计 | 本月预估已赚、年度目标、月度汇总、调薪生效日期 | P1 | 中到高 |
| 第四期 | 日常体验 | 菜单栏金额切换、上下班提醒、里程碑提示、配置导入导出 | P2 | 中 |

优先级表示建议实施顺序。复杂度是基于当前功能关系的初步判断，不能作为工期承诺。第一期建立统一的工作日判定，第二期在其上增加个人例外，第三期引入历史规则，第四期完善使用体验。

## 3. 第一期：中国节假日与调休

### 功能清单

- [x] 设置中增加“按中国大陆节假日及调休安排”开关。
- [x] 内置有官方来源的年度节假日与补班数据，离线可用（当前内置 2026；2027 尚未发布官方安排，按缺失年份处理）。
- [x] 识别法定安排中的休息日期和周末补班日期。
- [x] 展示当天状态及依据，例如“节假日休息”“调休上班”。
- [x] 当前班次、本年预估已赚和月薪折算共用同一套工作日规则。
- [x] 提示年度数据覆盖范围和缺失年份。
- [x] 建立新年度数据更新与校验流程（更新 `Sources/NiumaCore/Resources/china-holidays.json`、同步前端并运行两套核心测试）。

### 建议业务规则

1. 开关默认关闭，保留现有用户的每周排班设置。
2. 开启后，年度安排中的明确休息日和补班日覆盖每周排班，其余日期使用每周排班。
3. 月薪选择“按本月排班天数折算”时，分母使用调整后的实际排班天数；手动固定折算天数保持用户配置。
4. 开关变化后，按当前工资与新排班规则重新计算本年预估已赚，并在设置中说明。
5. 缺少某年数据时，明确提示并沿用该年的每周排班规则；不自行推算调休日期。
6. 原生 macOS 和 Tauri 使用同一份年度数据和等价判定规则。

上述规则仍需在实施前确认，尤其是自定义每周排班与全国安排的覆盖关系，以及节假日下月薪预估的展示口径。

### 验收标准

- [ ] 调休周末按工作日计算，明确放假的日期不创建新班次。
- [ ] 连续长假后可以正确找到下一次上班时间。
- [ ] 跨夜班按约定的班次归属规则计算，跨月、跨年不重复或遗漏。
- [ ] 自动折算与固定折算分别符合规则；调整后无排班日的月份有明确处理方式。
- [ ] 当前金额与年度累计使用一致的日历；切换开关后结果同步更新。
- [ ] 缺失年份有可见提示，断网不影响已内置年份的计算。
- [ ] 两套计算实现对同一配置、时间和年度数据给出一致结果。

## 4. 第二期：排班例外（按用户决定延后）

### 功能清单

- [ ] 指定某一天为上班或休息，并支持撤销该覆盖。
- [ ] 配置年假、事假等个人假期。
- [ ] 配置临时加班日期及工作时段。
- [ ] 提供近期排班日历，标明默认排班、全国安排和个人覆盖。

### 建议业务规则

个人指定日期的覆盖优先于全国安排，全国安排优先于每周排班。撤销个人覆盖后恢复下层规则。每个日期应能解释最终判定的来源。

个人假期是否计薪、临时加班如何估算金额、是否支持半天假，均需单独确认。日期标记和收入规则需要同时明确后实施。

### 验收标准

- [ ] 同一日期存在多层配置时，结果符合优先级且可解释。
- [ ] 新增、修改、撤销个人覆盖后，日历与收入同步更新。
- [ ] 重启后保留个人配置，旧配置能够兼容读取。
- [ ] 跨夜加班与原有班次重叠时，不重复累计计薪时段。

## 5. 第三期：收入统计

### 功能清单

- [x] 增加“本月预估已赚”（2026-11-05；[验证记录](verification/month-income-menubar.md)）。
- [ ] 设置年度收入目标并展示完成进度。
- [ ] 查看各月预估收入汇总。
- [ ] 为工资调整设置生效日期，按对应期间的工资规则估算。

### 建议拆分

2026-11-05 用户调整：先交付本月预估已赚，并提前实施第四期的菜单栏显示切换；年度目标、月度汇总和调薪历史本次不实施，已撤回试做内容。原拆分建议：先交付本月金额和年度目标，再实施月度汇总及调薪分段。前一部分沿用当前配置回算，后一部分需要保存带生效日期的工资规则，并明确它与历史排班的关系。

从旧版升级时无法自动恢复用户过去的工资和排班，应允许用户补录，并明确未补录期间采用的规则。历史估算仍需与实际到账金额区分。

### 验收标准

- [ ] 当前、本月、本年金额在相同口径下相互一致。
- [ ] 月份和年份切换时累计范围正确。
- [ ] 调薪生效前后分别按对应规则计算，跨夜边界有明确归属。
- [ ] 未设置年度目标、目标为零或已超额时，进度展示正确。
- [ ] 历史规则缺失时有明确说明，不生成虚构历史记录。

## 6. 第四期：日常体验

### 功能清单

- [x] 菜单栏可选择仅图标、当前班次已赚或本月预估已赚（提前实施）。
- [ ] 可选上下班提醒。
- [ ] 可选金额里程碑提示。
- [ ] 配置导出、导入与导入前校验。

### 建议业务规则

提醒默认关闭，由用户主动开启；通知权限被拒绝时收入功能仍可使用。金额隐藏应同时覆盖菜单栏、详情、设置和通知。导出前明确提示文件包含工资与排班，导入前展示将被替换的配置范围。

### 验收标准

- [ ] 菜单栏切换后金额与详情一致，隐藏金额后所有入口均遵守隐私设置。
- [ ] 提醒不因面板开关、休眠恢复或重复检查而重复发送。
- [ ] 未授权通知或关闭提醒时不影响收入计算。
- [ ] 无效或不兼容的导入文件不会覆盖当前有效配置。
- [ ] 导出后重新导入可恢复支持范围内的配置。

## 7. 各期共同交付要求

- 保持核心收入计算离线可用，新增能力不上传工资和排班。
- 每期更新需求说明、配置兼容规则、使用说明和实际验证记录。
- 对收入规则使用受控时间进行集成验证，覆盖正常路径、边界和失败路径。
- 原生 macOS 和 Tauri 分别记录构建与运行结果；未验证的平台明确标注。
- 回归设置窗口前置、金额隐藏、保存重载、休眠恢复和更新检查。
- 新增日历、统计与提醒后复核资源占用，保持按需刷新和低频写入。
