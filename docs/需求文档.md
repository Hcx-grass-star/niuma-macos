# 牛马上班鼓励小工具（macOS）需求文档

版本：v0.4 首版需求基线

日期：2026-11-04

状态：首版需求基线已补齐，原生工程及本机开发包已建立；实现和验收进展见 [本机验证记录](verification/native-baseline.md)。本文件不代表整体验收已通过。

> 用户已明确：制作 macOS 上班鼓励小工具，输入月薪或日薪、上班周期和每天上班时间，自动计算并只展示当前收入；月薪默认按本月排班天数折算，允许手动指定折算天数；优先使用菜单栏，主要适配本机 M5 芯片，并控制内存等资源占用。本版依据用户“补齐”指令，将上一轮推荐补充项落实为首版规则；资源数值作为开发和验收目标，不代表已经实测达标。

## 1. 产品定位

把上班时间转化为持续可见的收入进度，让用户在工作期间获得一点即时反馈和轻松的情绪鼓励。

一句话体验：设置一次工资和作息，工作时打开小工具，就能看到“这班现在已经赚了多少钱”。

目标用户是希望用收入进度获得上班动力的 Mac 使用者。产品中的金额统一称为“预估收入”，依据用户填写的工资口径估算；不推算税费、扣款、奖金或实际到账金额。

## 2. 首版目标与范围

### 2.1 成功标准

1. 用户能完成工资、上班周期、工作时间和休息时间设置，并只看到当前收入；日薪和时薪仅作为输入或内部计算依据，不另作收入指标展示。
2. 工作时收入自动增长；非计薪休息时停止；当班结束时达到当班收入上限。
3. 重启应用、锁屏或电脑休眠后，重新打开能按当前时间恢复正确的预估结果。
4. 用户能看到简短、可关闭的鼓励内容，无需频繁操作。
5. 在本机 Apple M5 上原生运行，并通过内存、CPU、磁盘占用及长时间运行检查；具体预算见第 7.4 节。

### 2.2 首版包含

| 能力 | 用户价值 |
| --- | --- |
| 月薪、日薪两种输入方式 | 适配不同的工资表达习惯 |
| 每周上班周期与每日时段 | 自动识别何时开始和停止计薪 |
| 非计薪休息时段 | 避免午休被错误计入 |
| 当前预估收入 | 用一个持续更新的金额呈现上班收入 |
| macOS 菜单栏入口及详情面板 | 随时查看，减少占用工作空间 |
| 轻量鼓励文案及关闭开关 | 提供适度情绪反馈 |
| 本地保存、金额隐藏 | 减少重复设置，保护工资隐私 |
| 可选登录后自动启动 | 每天登录 Mac 后即可使用，无需重复手动打开 |
| 安装、退出和设置清理 | 能在本机正常使用、结束运行和移除个人设置 |

### 2.3 首版不做，留待后续评估

以下能力不作为首版交付或验收要求；将来是否增加另行决定。

- 桌面悬浮窗、桌面小组件、宠物动画和主题皮肤。
- 大小周、轮班表、不同工作日使用不同作息。
- 指定日期的补班、请假及节假日自动同步。
- 加班工资、绩效、奖金、个税、社保及考勤对接。
- 月度收入统计、历史记录、调薪分段及数据导出。
- 账号登录、云同步、多人排行榜及收入分享。

首版先验证“收入实时增长是否带来上班动力”，避免工资核算和排班系统掩盖核心体验。

## 3. 核心使用流程

1. 首次打开，选择按月薪或日薪估算，填写金额。
2. 选择每周哪些天上班，设置每天上下班时间和非计薪休息时段。
3. 检查工资和作息设置；保存前如展示估算预览，只显示当前收入。
4. 保存后进入详情面板，自动显示当前状态和预估收入。
5. 日常通过菜单栏查看；需要时修改设置、隐藏金额或关闭鼓励内容。

没有完成有效设置时，不显示虚构收入，提示用户完成设置。保存失败时保留当前输入并允许重试；存在旧配置时，旧配置继续生效。

## 4. 输入与设置

| 设置项 | 规则 | 首版初始值 |
| --- | --- | --- |
| 工资模式 | 月薪、日薪二选一；切换时保留已输入内容，保存后以当前模式为准 | 月薪 |
| 工资金额 | 人民币，大于 0，最多两位小数；不接受空值、非数字或无限值 | 留空，由用户填写 |
| 上班周期 | 按周一至周日勾选，至少选择一天 | 周一至周五 |
| 上下班时间 | 精确到分钟；结束早于开始视为次日结束；开始与结束相同无效 | 09:00—18:00 |
| 非计薪休息 | 可不设，也可设多个不重叠区间；必须位于当班时间内 | 12:00—13:00，可删除 |
| 月薪折算方式 | 按本月排班天数，或用户指定折算天数；仅月薪模式展示 | 本月排班天数 |
| 指定折算天数 | 正数，可填写小数；启用指定折算时必填 | 留空 |
| 鼓励文案 | 是否展示面板内鼓励内容 | 开启 |
| 菜单栏收入 | 是否直接在菜单栏展示金额 | 关闭，仅显示图标 |
| 登录后自动启动 | 用户主动开启；展示实际生效状态；系统拒绝或撤销时说明原因 | 关闭 |

上班周期首版仅按每周固定星期选择，支持单休、双休及其他星期组合；不自动处理大小周、轮班、法定节假日或补班。所有勾选日共用一套作息。

休息默认 12:00—13:00 不计薪，可修改、删除或增加不重叠时段。用户需要带薪休息时，移除相应非计薪休息区间，该时段按正常工作时间估算；不另设休息工资比例。

有效计薪时长必须大于 0。单班跨度小于 24 小时；首版所有勾选工作日使用相同作息，不支持相邻班次重叠。

工资可以是用户选择的税前或税后金额；应用始终沿用该输入口径，不自行转换。金额输入附近说明：“请填写希望用于估算的工资金额。”

## 5. 工资计算规则

### 5.1 基本定义

- **班次归属日**：该班开始的日期，决定是否上班及所属月份。
- **有效计薪时长 H**：上下班之间的总时长，减去所有非计薪休息时长。
- **已计薪时长 E**：从当班开始到当前时间，实际落在计薪区间内的时长；范围为 0 至 H。
- **当班目标收入 D**：这一个完整班次对应的预估收入。

周期和作息是预设排班，不代表考勤记录。用户临时早退、请假或加班，首版不会自动感知；用户可通过设置查看工资和作息依据，不展示额外收入指标。

### 5.2 月薪模式

设月薪为 M，折算天数为 N：

```text
当班目标收入 D = M ÷ N
每小时预估收入 = D ÷ 有效计薪小时数
本班预估已赚 = D × E ÷ H
```

折算方式提供两种（用户已确认）：

1. **按本月排班天数，默认启用**：N 为该班归属月份内，符合所选每周工作日的日期数量。各工作日等额分摊月薪；月份切换时自动重新计算 N。
2. **按指定折算天数**：N 使用用户填写的正数。不同月份沿用该数值，除非用户修改。

第一种方式下，完整覆盖整个月排班的未舍入预估收入之和等于输入月薪；第二种方式下不保证相等。实际使用的 N 只在设置页折算说明中展示，收入面板不展示折算天数或其他计算指标。

本月排班天数只按每周周期计算，首版不自动扣除节假日或加入补班。固定折算方式可以调整估算基准，但不等于修正具体日期排班。

### 5.3 日薪模式

```text
当班目标收入 D = 用户输入的日薪
每小时预估收入 = D ÷ 有效计薪小时数
本班预估已赚 = D × E ÷ H
```

上班周期决定哪些日期存在班次，不改变用户输入的日薪。

### 5.4 时间与金额规则

- 到达上班时间自动开始，无需打卡。
- 到达非计薪休息时间停止增长，休息结束后继续。
- 到达下班时间停止增长，收入不超过当班目标；首版不额外计算加班收入。
- 计薪按经过的排班时间计算，与键盘输入、鼠标操作、窗口焦点无关。
- 锁屏、休眠、退出应用期间，处于计薪区间的排班时间仍参与估算；恢复时直接按时间重算，不依赖逐秒累加。
- 界面可见且处于计薪状态时，收入每秒更新；隐藏后重新打开时立即校正。
- 内部按未舍入金额计算，只在展示时四舍五入为两位小数，避免逐秒舍入带来误差。
- 按本机系统时区解释作息；时区或系统时间改变后重新计算，必要时提示用户检查设置。首版不保证手动改时期间金额单调增长。
- 涉及夏令时的地区，以班次开始至结束实际经过的时长计算；不存在或重复的本地时刻需要明确提示并让用户调整，不静默推断。

### 5.5 跨午夜班次

例如周一 22:00 至周二 06:00，整个班次属于周一。周二 00:00 不清零该班收入；月末跨月班次也沿用开始日期所在月份的折算基准。

跨午夜休息时间须明确标注“次日”，例如次日 02:00—02:30，避免与开始日期混淆。

### 5.6 修改设置

- 点击保存前展示新配置对应的计算预览；取消不改变当前配置。
- 保存成功后，按新配置重算当前班次，包括该班已经过去的时间。
- 保存前说明：“修改后会重新估算本班收入，显示金额可能变化。”
- 首版不维护历史工资账本，也不按调薪时刻拆分班次。

## 6. 状态与可见反馈

核心金额使用“当前收入”，附“本班预估”说明，指当前班次截至此刻的预估收入。主面板只展示这一个收入指标，另可保留状态和鼓励文案。

| 状态 | 当前收入 | 状态反馈 | 鼓励示例 |
| --- | --- | --- | --- |
| 尚未设置 | 不展示估算金额 | 提示完成设置 | 设置一下，看看时间值多少钱 |
| 上班前 | 展示即将开始班次的 ¥0.00 | 尚未上班 | 今天也慢慢来 |
| 工作中 | 金额自动增长 | 上班中 | 又攒下一点生活底气 |
| 非计薪休息中 | 保持当前金额 | 休息中 | 休息一下，待会儿再继续 |
| 当日已下班 | 保留当天已结束班次的最终金额 | 本班已结束 | 今日份辛苦，已经有了数字 |
| 休息日且没有正在进行的跨夜班 | 显示“—”，不沿用过期班次收入 | 休息日 | 今天的任务是好好生活 |

休息日判断必须先检查是否仍有前一天开始的班次。班次已结束且同一自然日还有下一班时，主面板切换到下一班“上班前”状态；不额外展示刚结束班次的收入指标。

不展示日薪、时薪、当班目标、收入比例、剩余工时、倒计时或历史累计。计算所需的中间值保留在内部。

## 7. macOS 使用体验

### 7.1 菜单栏入口（已确认）

菜单栏图标点击后打开详情面板，包含：

- 当前状态。
- 当前收入，标注“本班预估”，作为唯一收入指标。
- 一条鼓励文案。
- 隐藏金额、设置和退出入口。

设置保存成功后返回面板，并立即展示新结果。点击退出后应用结束运行，再次启动按已保存配置重算。

### 7.2 鼓励机制

- 工作期间，在计薪进度首次达到 25%、50%、75%、100% 时更新面板文案。
- 一次刷新跨过多个节点时，只展示当前最高节点，不连播已错过的内容。
- 同一班次内不重复触发同一节点；重新打开面板不额外弹出提示。
- 首版不发送系统通知，不播放音效；关闭鼓励后保留当前收入显示。
- 文案轻松、支持用户休息，避免羞辱、攀比以及鼓励加班。

### 7.3 隐私与基础体验

- 工资和作息保存在本机，核心功能离线可用；首版不上传这些数据。
- 一键隐藏所有界面中的工资、收入及工资预览金额，以“••••”替代；再次点击恢复，隐藏状态重启后保留。
- 默认菜单栏只显示图标，避免工资直接暴露在共享屏幕中。
- 支持深色与浅色外观，主要操作可通过键盘完成。
- 不申请辅助功能、屏幕录制、定位等与工资估算无关的权限。
- 以 macOS 13 Ventura 为最低支持版本，覆盖 Ventura、Sonoma、Sequoia、26、27 等主流版本；交付通用二进制，Apple Silicon 与 Intel 机型均为原生运行。本机 Apple M5、macOS 27.2 为首个实机验证环境，其余版本与机型须在对应环境单独验证。

### 7.4 本机适配与资源预算

**已核实的本机环境**：Apple M5、arm64、24 GiB 内存、10 个逻辑 CPU，macOS 27.2（26B123）。依据为本机 `sw_vers`、`uname -m` 和 `sysctl` 的只读输出，核实日期为 2026-11-04。

**用户已确认的要求**：优先适配这台 M5 Mac，并控制内存等资源占用；同时要求主流 macOS 版本均可使用。交付应包含 arm64 与 x86_64 通用可执行文件，两种芯片上均以原生架构运行，不依赖指令转译。

以下预算按本轮“补齐”指令采用为首版开发与验收目标；这是工程目标，不是现有原型或未来应用的实测结果。不能在未达标时直接修改报告口径或宣称达标，调整目标须说明原因及影响。

| 指标 | 目标 | 测量范围 |
| --- | --- | --- |
| 后台常驻内存 | 不超过 50 MiB | 菜单栏仅显示图标，收入面板和设置均关闭 |
| 展开面板内存 | 不超过 80 MiB | 收入面板展示、每秒更新，或设置页正常操作；分别测量 |
| 后台平均 CPU | 不超过 0.5% | 单核心满载为 100%，稳定采样 10 分钟 |
| 收入面板平均 CPU | 不超过 2% | 单核心满载为 100%，每秒更新，稳定采样 10 分钟 |
| 应用磁盘占用 | 安装后的 `.app` 不超过 30 MiB | 正式交付包，包含所有随附资源和运行依赖；不含开发工具 |
| 应用数据占用 | 配置、缓存和应用自行生成的日志合计不超过 1 MiB | 不含系统管理的诊断文件；不按秒保存收入历史 |
| 再次打开面板 | 点击到显示正确收入不超过 300 毫秒 | 应用已启动，正常系统负载，连续操作 20 次并报告最慢值 |
| 长时间运行 | 连续运行 8 小时，无崩溃、收入错误或持续内存增长 | 同一排班配置及相同界面状态下，对比早晚稳定采样窗口 |

内存统一按应用的 physical footprint 口径记录，同时报告阶段峰值；不同工具口径不能直接混用。包含应用自身及专用辅助进程，开发器和浏览器原型占用不作为正式应用结果。稳定采样前预热 60 秒，内存预算以采样窗口内最大值判定；启动及首次加载瞬时峰值另行报告，不隐去。

**降低占用的行为约束**：

- 收入面板可见且正在计薪时，按秒更新金额；不加入持续的粒子、视频或高帧率背景动画。
- 默认仅显示菜单栏图标时，面板收起即停止秒级刷新；再次展开时根据当前时间计算，不补跑错过的逐秒任务。
- 如果用户开启菜单栏金额展示，只有需要显示增长中的金额时才进行秒级更新；该模式单独测量 CPU 和能耗，不能套用“后台仅图标”的结果。
- 未上班、非计薪休息和下班后，无需逐秒刷新金额；按必要状态切换或再次打开触发更新。
- 工资估算不阻止系统休眠、不因刷新工资主动唤醒睡眠中的电脑；唤醒后重算。
- 鼓励内容随必要状态或收入节点更新，不启动独立的高频刷新任务。
- 修改设置时才保存配置，不逐秒写文件，不持续请求网络。
- 退出应用后不保留专用后台服务或工资刷新进程。

这些约束与 Apple 关于减少无用定时器、在不再需要时停用重复定时器的建议一致，参见 [Apple：Mac 应用能效指南——减少定时器使用](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html)。该指南支持节能方向，不证明本产品能达到上述数值。

**可行性评估及验证边界**：首版只有一个收入指标、本地配置和少量文本，采用原生轻量实现。技术方案和实际构建须检查随附运行时、字体图片和辅助进程是否满足预算；当前仅有开发阶段的验证，不能声称完整资源目标已达成。若测量超出预算，应先定位并优化，再记录无法满足的指标与取舍，不能用本机总内存较大替代达标验证。

### 7.5 菜单栏展示和登录启动

- 默认仅显示菜单栏图标，点击后展开当前收入面板；无需保留常驻主窗口或 Dock 图标。
- 开启“菜单栏显示当前收入”后，菜单栏直接展示同一班次的当前收入，与展开面板保持一致，不增加日薪、时薪或累计收入指标。
- 菜单栏金额在休息时保持、下班后封顶；上班前显示 ¥0.00；无当前班次的休息日仅显示图标。
- 开启隐藏金额时，面板和设置中的金额以“••••”代替，菜单栏退回图标；恢复显示后按原来的菜单栏偏好展示。
- “登录后自动启动”默认关闭。用户在设置中主动开启后，后续登录当前 Mac 账户时启动一次应用；本次登录内主动退出后不自行重启。
- 启动成功后仅驻留菜单栏，不自动弹出收入或工资设置，不主动暴露工资。
- 关闭自动启动后，下次登录不再由该设置启动。若系统要求用户确认、拒绝或撤销授权，界面展示实际状态并提供处理说明，不显示虚假的“已开启”。
- 重复打开应用只使用一个实例和一个菜单栏入口，不能重复计算或叠加后台刷新任务。

### 7.6 安装、退出、更新与卸载

| 操作 | 预期结果 | 失败及恢复 |
| --- | --- | --- |
| 首次安装 | 提供本机可运行的 arm64 `.app`，复制到“应用程序”后可启动；首次使用无工资配置，进入设置 | 安装或启动受阻时记录实际错误并解决构建、签名或权限问题，不能将“已有文件”视为安装通过 |
| 正常启动 | 已配置时只显示菜单栏入口，打开面板后立即按真实时间估算收入 | 配置缺失或无法读取时提示重新设置，不显示虚构收入；确认修复前不覆盖现存文件 |
| 关闭面板 | 应用继续在菜单栏运行，按资源规则停止不必要刷新 | 再次点击菜单栏即可展开，无需重新输入工资 |
| 退出应用 | 通过面板的“退出”入口结束应用，移除菜单栏入口并释放专用进程；保留已保存设置 | 再次手动启动恢复设置，按当前时间重算，不按退出期间逐秒补跑 |
| 更新应用 | 先退出，再用新版本替换 `.app`；同一应用身份下保留有效配置和展示偏好 | 配置不兼容或读取失败时明确说明并引导修复，不静默清空；首版无需自动下载更新 |
| 卸载应用 | 用户先关闭自动启动并退出，再将 `.app` 移入废纸篓 | 删除 `.app` 不等于清除设置；彻底清理须先执行第 7.7 节的重置，或按交付说明移除应用专属数据 |

首版交付面向本机使用，不要求 App Store 上架；正式交付需在这台 M5 Mac 上从实际交付文件完成安装验证。

### 7.7 清除设置与数据边界

- 设置页提供“清除设置并重置”入口。触发后确认一次，明确将清除工资、作息、折算方式、显示偏好、隐藏状态、鼓励开关及自动启动设置；用户取消时不改变任何数据。
- 确认后先关闭应用管理的自动启动，再删除应用自己的配置、缓存和日志，恢复首次使用状态；不展示旧收入，不保留工资历史副本。
- 重置成功后回到首次设置，工资为空、菜单栏仅图标、自动启动关闭，其他初始值按第 4 节恢复。
- 自动启动关闭失败时，先停止后续清理并说明当前状态；数据清理部分失败时，列出尚未清理的应用数据范围并允许重试，不宣称“已全部删除”。
- 重置只处理本应用拥有的数据，不能删除用户导出的文件、其他应用数据或系统日志。首版不提供收入导出功能。
- 交付说明必须列出实际采用的配置、缓存、日志目录及偏好存储位置；不得只写猜测路径。应用自行记录的日志不得包含工资金额或可恢复的工资配置。
- “清除设置”不会自动删除应用本体；“卸载应用”也不隐含清除所有个人设置，两者在说明中分别写清。

### 7.8 资源与真实运行的验收执行

资源预算采用第 7.4 节所列目标作为首版开发约束。验收使用正式发布构建，在本机 M5 上进行，不能用浏览器原型、调试器附加进程或演示时钟替代。

1. **安装与设置**：从实际交付文件完成安装，验证空配置、正常保存、取消修改、异常输入、隐藏金额和重启恢复。
2. **计算正确性**：核对第 8 节金额样例、月薪两种折算、带薪与非计薪休息、跨午夜及跨月；边界样例可用受控时间的集成验证，但必须注明方法。
3. **真实时间运行**：至少一次跨过真实计薪与非计薪边界；验证面板收起后重新展开、正常退出后重开、锁屏及休眠唤醒，金额与实际经过的计薪区间一致。
4. **后台与展示模式**：按规定预热并分别采样仅图标、展开收入面板、设置页和菜单栏金额四种模式，记录 CPU、内存、峰值及采用的测量工具和版本。菜单栏金额模式采用与展开收入面板相同的内存、平均 CPU 预算。
5. **长时间稳定性**：连续运行 8 小时，记录内存曲线和操作事件。在相同配置及仅图标状态下，对比预热后第一个 10 分钟与结束前 10 分钟的内存中位数；后者增量目标不超过 5 MiB，同时不得出现反复开关面板后阶梯式不回落的持续增长。超过增量目标时须定位并优化，不能仅以未超绝对内存预算判定通过。
6. **生命周期与磁盘**：验证自动启动开关、重复打开、退出无专用进程残留、更新保留设置、重置及卸载路径；记录应用体积和应用自行保存的数据占用。

验收报告逐项记录执行环境、构建标识、操作、预期、实测、证据及状态。状态区分“通过、失败、未测试”；模拟时间证据与真实时间证据分别标注。8 小时运行未完成、资源超预算或关键恢复场景未验证时，不得将正式应用标记为验收通过。

## 10. 交付边界

现有原型尚未覆盖登录自动启动、真实持久化、安装卸载和系统资源管理；新增需求以本文为准，不能依据原型按钮或演示行为判定这些能力已完成。
