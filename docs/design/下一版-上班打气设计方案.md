# 牛马上班：下一版「给上班加点盼头」

日期：2026-11-12。状态：设计提案与独立可交互 Demo，业务规则待评审；未接入正式客户端，未指定发布版本号。

> 实施跟进（2026-11-12）：原生 macOS 已进入实现与集成验证，本文保留设计提案语义；实际已验证内容与限制以 [原生验证记录](../verification/cheer-features.md) 为准。

## 1. 定位与现有基础

目标：让「看工资增长」延伸成三种轻量正反馈——回来有战报、努力有目标、情绪有出口。保持菜单栏工具的低打扰、离线与低资源方向。

已检查的本地依据：

- `Sources/Niuma/IncomeViewController.swift`：原生收入面板宽度 340pt，展示当前、本月、本年金额，金额隐藏与倒计时入口已存在。
- `Sources/NiumaCore/IncomeEngine.swift`：按班次、排班与非计薪休息回算收入；区间计薪已有内部方法，但尚未提供任意区间的公开 API。
- `Sources/Niuma/WorkReminderCoordinator.swift`：现有工作提醒使用本地通知，正文不包含金额。
- `README.md`、`frontend/`、`shared/`：同时存在原生 macOS 与 Tauri 共享实现，当前收入不是历史工资账本。
- `docs/功能迭代清单.md`：年度目标仍是规划，不能把愿望功能当作已有年度目标的小改版。

本提案不依赖用户粘贴竞品描述的真实性，也不把竞品实现细节当成已验证平台能力。

## 2. 信息架构与视觉

主面板沿用约 340–360pt 的紧凑宽度，默认仍进入「收入」。采用四个短标签：收入 / 战报 / 愿望 / 木鱼。现有设置、倒计时和用户选择显示哪些收入的能力在正式实现中保留；Demo 聚焦三个新增功能，没有复制全部旧设置。

收入页从上至下：收入卡片 → 首个愿望摘要 → 战报与木鱼快捷入口 → 原倒计时和设置区。战报、愿望、木鱼在同一面板内切换，避免另开常驻窗口。

视觉：系统中文字体、等宽金额、低饱和鼠尾草绿、普通浅色背景；深色可切换。金额仍是首页主视觉，木鱼仅在专页出现。普通材质作为默认，不要求开启液态玻璃。Demo 的桌面背景及左侧说明仅用于评审，不属于客户端。

## 3. 摸鱼战报

### 用户流程

用户主动开启 → 应用运行期间记录一次可信离开起点 → 返回 → 校验同一会话与计薪规则 → 生成最近一条战报 → 可选通知提醒查看。

推荐规则（本次为可修改的设计假设）：

1. 新功能默认关闭，用户主动启用；Demo 为便于体验预先打开开关。
2. 离开满 2 分钟、存在计薪时段、显示金额四舍五入后大于 0，才生成战报。零收入与短离开不发通知，不覆盖旧战报。
3. 计算区间采用 `[离开时刻, 返回时刻)` 与既有计薪区间的交集。跨午休扣除非计薪部分，跨班次、跨月、跨年按各班次规则拆分。战报金额不再次累加到收入。
4. 文案：「欢迎回来，辛苦了」「离开 15 分钟，预估收入 +¥15.63」。避免断言用户没有工作或企业“白发工资”。
5. 系统通知始终不含金额、目标名、工资或功德；显示「离开期间，收入又向前走了一点。打开牛马上班查看战报」。隐私模式下战报正文金额也打码。
6. 通知未授权、专注模式拦截或通知开关关闭，只影响系统提示；面板结果仍可见。点击通知进入战报页是原生实施目标，Demo 只展示页面内预览与关闭。
7. 重复离开事件保留第一个起点；重复返回忽略；无起点不补算。重启不从旧离开事件补发；本期只保留最近一条会话内战报。
8. 离开期间工资/作息发生变更、时区变化、时钟回拨或记录无法解释，取消该次战报并说明「本次规则发生变化，未生成战报」。正常收入仍由现有引擎计算。
9. 锁屏与系统休眠可能交叠，须共用一次离开会话，避免双算。无法确认锁屏信号时不以“屏幕熄灭”冒充锁屏。

### 示例与边界

| 输入 | 预期 |
| --- | --- |
| 日薪500，计薪8小时；工作中离开15分钟 | 500 / 8 / 60 × 15 = 15.625元，显示 +¥15.63 |
| 11:50离开、12:10回来，12:00起非计薪午休 | 仅10分钟计薪，显示 +¥10.42 |
| 下班后离开30分钟 | 不生成新战报，不增加收入 |
| 工作中离开30秒 | 收入按正常规则增加，不生成新战报 |
| 通知权限拒绝 | 面板保留结果，不反复请求权限 |
| 重复解锁、跨月、休眠恢复、修改系统时间 | 前两者需幂等及正确分段；异常规则取消，不猜测补算 |

## 4. 愿望清单

### 用户流程

添加名称、目标金额、已有金额 → 保存时建立累计起点 → 首页展示首个愿望 → 在愿望页查看最多3个目标 → 编辑或删除 → 达成时显示标记，用户自行决定是否奖励。

推荐口径：**进度 = 已有金额 + 创建后新增预估收入**。已有金额是用户手动输入的预算，不校验银行余额；本功能不提供记账、扣款或购买。

- 名称去除首尾空白，1–20字；目标为0.01–99,999,999元；已有金额为0–99,999,999元，金额最多两位小数。
- 新建从保存时开始，不自动把本月/本年已赚全部算进目标。默认示例耳机视为本班开始创建，已有2400元，加本班312.50元，共2712.50元。
- 多愿望独立展示同一新增收入，不是资金分配。每条都明确提示这一点；首版不增加“分配比例”体系。
- 金额可超过目标，进度条上限100%；不隐藏超额金额，不自动删除或清零，不设置完成后自动购买。
- 编辑名称、目标及已有金额保留原创建起点；删除不改工资。Demo 删除仅影响可重置的页面示例数据。正式持久化版本建议加删除确认或撤销入口。
- 隐私模式隐藏金额、百分比、进度条填充、完成标记，并阻止打开包含价格的编辑表单；愿望名称可保留。
- 不展示未经验证的「还要工作几天」，避免节假日、非工作时间及调薪造成虚假精确性。
- 正式版若要求“创建后累计”长期稳定，不能直接使用 `本年当前值 − 创建时本年值`：跨年会归零，调薪也会回算历史。建议按配置生效区间结算已累计值，区间沿用统一计薪算法。工资/排班变更前结算旧规则，之后用新规则；跨年不重置。未建立这条链路前只能交付愿望展示原型，不能声称稳定储蓄功能已完成。
- 正式持久化建议独立版本化配置文件，原子保存；迁移失败不影响旧工资设置。累计金额不低于0，时间异常不补算。实际到账与预估有差异时，可编辑已有金额调整。

## 5. 敲敲木鱼

- 手动点击或键盘聚焦后空格敲击：木槌轻敲、短促缩放、出现「功德 +1」；当前会话计数加一。
- 非工作时仍可手动敲；自动敲默认关闭，开启后仅工作中、木鱼页正在展示、面板打开且应用可见时每1.5秒敲一次。
- 面板收起、页面切换、锁屏、午休、下班时停止调度；恢复工作且重新展示才恢复。不做后台0.8秒常驻动画。
- 音效默认关闭；开启后播放短音，关闭不影响动画。尊重降低动态效果设置，降为静态计数反馈。
- 功德与收入完全独立，不建立排名、连击任务、打卡惩罚、金币兑换或通知轰炸。首版无需图片生成、联网资源或复杂游戏系统。

## 6. 实现范围与依赖建议

这是后续实现落点建议，不是已验证技术方案：

| 模块 | 原生 macOS 建议落点 | 依赖/风险 |
| --- | --- | --- |
| 区间计薪 | NiumaCore/IncomeEngine 的统一区间入口 | 扣休息、班次归属、跨月跨年精度；不另写第二套公式 |
| 离开与返回 | 独立会话协调器，接入 AppDelegate 生命周期 | 锁屏、休眠、唤醒来源去重；真实系统版本验证 |
| 战报展示及通知 | 收入面板切页；复用通知权限体验 | 权限拒绝、隐私、专注模式，点击通知路由 |
| 愿望配置及累计 | 独立模型与原子存储，接入工资变更生效点 | 是本次最需要补齐的数据链路，不能只存一个进度百分比 |
| 木鱼 | 按需创建的 AppKit 视图 | 定时器随面板释放，声音句柄和动画及时结束 |
| Tauri | 共享收入区间计算与等价业务规则 | 系统事件能力单独实现，不能直接套用 AppKit 通知 |

先交付原生 macOS；Tauri/Windows 行为一致性作为后续单独验收范围的建议，待版本范围确认。此次没有改动任何平台生产代码。

技术资料状态：已尝试 Context7（配额耗尽）、DeepWiki（工具策略禁止调用）及官方网页查询（未返回可引用正文）。因此未核实 `com.apple.screenIsLocked/Unlocked` 等非公开事件名的稳定性，也不承诺“两个通知即可完成”。实施前须重新验证公开API与 macOS 13+真实行为，包括切换用户、睡眠恢复、面板收起、拒绝通知权限。候选官方入口：Apple NSWorkspace 会话/屏幕/睡眠通知及 UserNotifications 授权文档；这些入口目前只能作为待查来源，不能当作本次验证证据。

## 7. Demo 使用与验证范围

入口：`prototype/cheer-next/index.html`。无构建、无第三方资源，双击即可离线打开；也可使用仓库目录的本地 HTTP 服务。

1. 首页看愿望摘要；左侧选择场景，点「模拟锁屏离开」，再点「模拟解锁返回」。
2. 进入愿望，新建「周末去海边」，目标30元、已有0元；快进计薪30分钟后应达成，金额31.25元。
3. 进入木鱼，手动敲击并开启自动敲；切到收入页后应暂停。收起面板也应暂停。
4. 隐藏金额后检查菜单栏、战报、愿望及快进提示；切换深浅色。
5. 页面刷新或「重置演示」恢复示例；所有示例数据只驻留当前页面。

Demo 不是实机功能：不锁屏、不监听真实系统事件、不获取正式工资、不发系统通知、不写正式配置。演示时钟为固定场景标签；离开与快进操作直接推进金额，不代表一条连续真实排班时间线。午休及跨年等完整计算仍以正式收入引擎和未来集成验收为准。

实际验证记录见同目录 `下一版-上班打气Demo验证.md`。

## 8. 版本评审要点

建议本轮评审重点：四标签与首页密度是否合适、2分钟门槛是否合适、愿望是否接受“独立预估进度”的口径、木鱼是否默认静音、正式版是否只先落地原生macOS。以上是可调整建议，不冒充已确认产品决策。
