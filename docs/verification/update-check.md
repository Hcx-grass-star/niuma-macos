# 自动检测更新验证

日期：2026-11-05。范围：用户确认的启动检查、24 小时自动限频、开关、手动检查、新版说明和发布页入口；不包括自动下载安装。

## 验证结果

| 范围 | 直接证据与结论 |
| --- | --- |
| 功能缺失时的 RED | 首次执行本地更新测试，因尚无共享更新模块而失败；实现后进入 GREEN。未将缺少模块描述为已复现线上故障 |
| Swift 与 JS HTTP 集成 | `npm run test:updates` 启动隔离本地 HTTP 服务，两种实现读取与 GitHub 形状相同的响应；覆盖新版、相同或更低版本、草稿、预发布、无正式发布、不同平台安装包、无效 URL/JSON、限流、服务错误、超时和断连 |
| 时间规则 | 首次、关闭、24 小时内、恰好 24 小时、时钟回退均验证；手动请求由调用层绕过自动限频 |
| 收入回归 | 原生现有 10 组收入/存储集成及 JavaScript 收入核心继续通过 |
| 原生 UI 控制器 | 临时 AppKit 验证程序使用实际设置窗口及更新控制器、独立 UserDefaults 测试域和本地 HTTP。验证版本入口、手动最新状态、自动开关持久化、检查时间持久化、重建控制器后限频、新版弹窗和重置偏好。提示框由模态循环测试定时器关闭；未读取或修改用户工资文件，不等价于已安装应用整体端到端验收 |
| 前端操作 | ego-browser 操作实际页面，本地 HTTP 替代外部版本响应。启动自动请求 1 次；24 小时内重启为 0 次；关闭后重启为 0 次；重新开启但仍在 24 小时内为 0 次；手动检查额外请求 1 次 |
| 新版与错误展示 | 新版首页入口、设置页版本和纯文本说明可见；说明中的 HTML 标记未被解析。手动最新版、限流状态明确；限流后收入仍正常显示 |
| 下载入口 | 前端点击产生本仓库正式版本页 URL；另用模拟 Tauri 桥验证发出 `open_release_page` 命令及参数。未将模拟桥视为系统浏览器进程或 Windows 原生验证 |
| 前端外观 | 检查 390×640 视口下的浅深色更新设置布局，可滚动查看说明与按钮 |

## 真实服务与构建边界

- 用正式 Swift `UpdateService` 只读请求真实 GitHub 接口，结果为“更新服务暂时受限，请稍后重试”。此前 HTTP 探测确认过公开出口的限流响应。没有将其视为已是最新版或已发布可下载新版。
- 原生使用项目本地依赖构建 arm64/x86_64 通用应用成功，应用包版本为 0.2.0；`codesign --verify --strict` 通过（本地临时签名）。现有 SDK 搜索路径及兼容库警告没有阻断构建。
- 本机仍缺少 Rust/Cargo，Tauri 安装包及其新增系统浏览器命令未完成原生编译和 Windows 真机验收；前端和共享 HTTP 结果不能替代这些检查。
- 没有创建 GitHub Release、推送代码或上传安装包。本次测试的 v0.3.0 仅为隔离样例。
- 更新检查使用公开版本信息，不传输工资、作息或 Token；无第三方依赖新增。原有长时资源、登录启动和休眠实机验收范围不因此改变。
