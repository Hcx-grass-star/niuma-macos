# 原生上班打气功能验证

日期：2026-11-12。范围：Swift/AppKit 原生 macOS 开发版。Tauri/Windows 未修改；本次未发布正式版本。

> 后续图标与导航视觉修正、当前检查结果及未闭合焦点回归见 [图标与导航验证](icons-navigation.md)。下述源码指纹属于原先功能交付的构建。

## 实现

- `Sources/NiumaCore/IncomeEngine.swift`：任意区间收入与实际计薪时长，复用原班次、非计薪休息、节假日及跨月折算。
- `Sources/NiumaCore/Cheer.swift`：愿望、累计检查点、格式校验、独立原子存储、离开事件去重与自动木鱼策略。
- `Sources/Niuma/AppDelegate.swift`：真实系统事件注册、战报生成与通知、点击通知路由、配置生效区间结算、写入失败工资回滚、退出与重置清理。
- `Sources/Niuma/CheerContentView.swift`、`IncomeViewController.swift`：收入/战报/愿望/木鱼四页、行内愿望编辑与删除确认、统一隐私、手动与自动木鱼、默认静音及降低动态效果处理。
- `Sources/Niuma/SettingsWindowController.swift`：首次预览延迟到所有选择器初始化后，修复日薪设置页初始化访问-1索引的崩溃。
- `Sources/Niuma/IncomePanel.swift`：最终尺寸变化时同步普通内容容器，避免切页后的旧高度裁切标题。

愿望采用独立预估口径，不追溯创建前收入；跨年不清零。调薪先按旧规则结算，再保存新规则。文件重载可补算应用退出期间同一规则的计薪时段；无法解释的规则、时钟或时区变化不补算，已有进度保留。

`cheer.json` 位于当前包环境的工资配置目录，包含计薪规则副本用于结算，不包含离开历史。战报及功德仅保留本次应用会话。默认不创建示例愿望；战报、自动木鱼与声音需用户主动开启。系统通知正文不含金额或愿望名称。

## 未验收与平台约束

1. 自动测试直接注入应用事件处理入口和受控时间，没有主动锁定用户电脑。真实锁屏/解锁、睡眠/唤醒、屏幕事件交叠、快速用户切换仍需用户环境的实机检查。
2. Apple官方文档JSON已核实：NSWorkspace用户会话通知指用户切换，屏幕睡眠通知指屏幕熄灭，不能等同锁屏。`com.apple.screenIsLocked/Unlocked`作为兼容信号使用，非公开稳定API承诺。若平台不发送该信号，单纯锁屏且未触发屏幕/休眠事件可能没有战报；信号丢失也可能导致本次会话无法结束。
3. 未验收真实通知授权拒绝、专注模式、横幅交付及点击通知路由；代码已接入本地通知和路由，但不能将注入事件测试当成实际送达证明。
4. 未听验音效，未在开启系统降低动态效果后实测；代码有相应开关和分支。
5. 未完成macOS13/Intel真机、8小时运行、600秒资源窗口或公证分发验收；通用构建不代表所有系统和机型的设备验收。
6. 未移植Tauri/Windows。原设计中的竞品信息未作为平台API证据。

## 建议手工试用

打开开发包，先填写开发环境的工资与作息。在战报页开启生成战报；工作中主动锁屏超过2分钟后回来，检查计薪时段交集、最近战报和通知。分别跨午休、下班、休眠恢复尝试，并在隐藏金额后确认所有新入口均打码。愿望可建立小目标观察进度；木鱼页开启自动后切页或收起面板确认暂停。测试应用与数据均标注开发环境，勿把示例或开发配置当作正式工资数据。
