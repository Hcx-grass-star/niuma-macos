## 技术方案与结构

采用 Swift + AppKit：系统菜单栏、原生弹出面板、原生设置窗口。没有 WebView、浏览器进程或外部后台服务。

- `NiumaCore` 负责输入校验、按班次日期折算、休息扣除、跨夜跨月和原子文件保存。
- `Niuma` 负责界面、单实例、系统登录启动接口和按需刷新。仅图标且面板收起时不安排收入刷新任务。
- 收入视图按需创建；面板关闭后释放。设置窗口关闭后释放草稿与窗口引用。
- 收入由真实时间直接重算，不保存逐秒累计值。内部比例只用于鼓励文案，界面只显示当前收入。
- 配置保存在应用专属目录，目录创建权限为当前用户独占；不写入工资日志，不保存收入历史。

依据：[Apple NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem)、[Apple NSPopover](https://developer.apple.com/documentation/appkit/nspopover)、[Apple Mac 定时器能效指南](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html)。AppKit API 通过 Context7 及本机 SDK 核对；DeepWiki 返回校验页，未将其作为有效技术证据。

## 原生界面检查

通过本机原生应用操作完成，不使用网页原型代替：

- 首次启动工资为空，打开工资与作息设置。
- 输入负工资后点击保存，显示具体校验错误，输入保留。
- 输入示例月薪 ¥21,000 并保存，自动返回“当前收入”面板，金额随真实时间变化。
- 主面板只有当前收入、状态和鼓励，没有时薪、日薪、目标、百分比或倒计时。
- 隐藏金额后主面板为“••••”，设置页工资使用安全文本框，当前收入预览也隐藏；恢复后可查看收入。
- 设置快捷键可打开已有配置，配置确实由文件重载；该检查不等价于真实重新登录或休眠恢复。
- 收入面板已设置可访问标题与键盘焦点，能够由原生自动化读取；这是本机 UI 可访问性检查，不代表完整无障碍认证。
- 登录启动界面显示系统实际未找到应用的状态，没有虚报已经开启。未进行注册及重新登录验收。

界面测试只使用本轮输入的示例配置。该工资不代表用户真实工资；不得将测试配置作为新用户默认值。

## 资源基线

采用 `scripts/measure-resources.swift`，使用 libproc 的 physical footprint 和累计 CPU 时间；单核心满载记为 100%。采样工具是独立进程，其占用不计入应用。

采样只记录被测应用的可见窗口尺寸，用于识别面板已自动收起的情况；不截图，不读取其他应用的标题或内容。报告保留逐秒样本、构建指纹和进程生命周期内存峰值。

120 秒采样的前 60 秒作为预热，后 60 秒作为开发阶段稳定窗口；它不满足需求中每种模式 600 秒的正式验收时长。窗口几何查询为空只代表没有检出，不单独作为“面板已收起”的证明；还需结合启动路径及实际操作记录确认模式。
