# 发布与更新

从 0.2.1 起，两版应用优先读取 `https://hcx-grass-star.github.io/niuma-macos/latest.json`。静态清单有效时不请求 GitHub REST API；清单缺失、超时、网络失败或内容无效时，再请求 `https://api.github.com/repos/Hcx-grass-star/niuma-macos/releases/latest`。双源失败会明确报错，不冒充“已是最新版”。

## 发布步骤

1. 同步版本号：`Resources/Info.plist` 的 `CFBundleShortVersionString`、`package.json`、`package-lock.json` 的顶层和根包版本、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`，同时递增原生 `CFBundleVersion`。版本使用三个数字段，例如 `0.2.1`。
2. 执行 `npm run test:core` 和 `npm run test:updates`。验证收入、静态主源、备用 API、平台筛选、版本和错误状态。
3. macOS 执行 `bash scripts/package-release.sh`。Windows 在 Windows 开发机或现有 Windows 构建工作流构建，并在对应平台安装验收。
4. 在本仓库创建正式 Release，例如 `v0.2.1`，填写说明并上传已验证的安装包；不要勾选预发布。仅推送标签或上传 Actions Artifact 不等于发布可下载版本。
5. 正式发布及安装包上传完成后，执行 `npm run publish:updates`。此命令使用发布者本机已有的 `gh` 登录，读取真正的 latest 正式 Release 和已上传安装包，条件写入 `codex/update-feed` 分支的 `latest.json`；可先运行 `npm run publish:updates -- --dry-run` 预览。凭据只在发布机器使用，客户端不嵌入 Token。
6. 等待 GitHub Pages 部署完成，读取上述公开 `latest.json`，确认版本、发布页及安装包。Pages/CDN 可能有短暂缓存（本次观察到 `max-age=600`），不能把仅提交清单当作部署完成。最后用已具备此检查逻辑的低版本应用手动检查、下载并验证。

静态站点已配置为从 `codex/update-feed` 分支根目录发布；该分支只含公开版本清单、`.nojekyll` 和简单下载入口，与工作代码分离。后续普通发布只需第 5 步同步清单，分支提交会触发 Pages 部署。脚本拒绝回退清单版本，使用文件 SHA 防止竞争覆盖；重复发布相同内容不产生提交。没有设置自动发布工作流。

## 清单与安装包

清单字段为 `version`、`notes`、`url`（正式发布页），以及可选的 `macos` / `windows` 直接安装包 URL。没有某平台安装包时省略该字段，客户端明确显示该平台暂不可用。只允许本仓库、匹配标签和平台扩展名的地址；说明作为纯文本显示。

- macOS：`.dmg`，或文件名包含 `macOS`（忽略大小写）的 `.zip`。建议英文文件名 `niuma-0.2.1-macOS-universal.zip`，避免 GitHub 自动移除中文字符。
- Windows：`.exe` 或 `.msi`。
- 下载按钮继续打开本仓库 `/releases/tag/<标签>` 页面，用户选择适合自己的安装包；没有自动安装和架构自动选择。

## 升级及故障边界

- 已安装 0.2.0 的检查逻辑仍只使用 API，本次修复不会远程改写旧应用；首次升级到 0.2.1 需直接前往发布页下载并替换 `.app`，保留工资和排班配置。
- 原生版本来自包内 Info.plist；Tauri 版本来自 `AppHandle.package_info()`；浏览器预览清单由 `npm run sync:frontend` 从 package.json 生成。
- 原有自动开关、24 小时限频和手动检查不变。每个来源最多等待 10 秒，只有主源失败才发起备用请求；网络失败不影响收入计算。
- 静态托管消除了对匿名 REST API 额度的直接依赖，但不是断网或所有托管服务永不受限的保证。双源都失败时保留错误，不保存工资或排班到远端。
- 开发分发包使用临时签名；更新检查不替代 Apple Developer ID、公证或 Windows 分发验收。

参考：[GitHub Pages 静态托管](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[配置 Pages 发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
