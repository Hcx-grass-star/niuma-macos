# 发布与更新

自动检测使用 `https://api.github.com/repos/Hcx-grass-star/niuma-macos/releases/latest`。本地构建不会自动上传或发布；只有 GitHub 上已有正式 Release 和匹配安装包，其他用户才能检测到可下载的新版。

## 发布步骤

1. 同步正式版本号：原生 `Resources/Info.plist` 的 `CFBundleShortVersionString`、`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`。同时递增原生 `CFBundleVersion`。版本格式为 `主版本.次版本.修订版本`，例如 `0.3.0`。
2. 执行 `npm run test:core` 和 `npm run test:updates`；两版均应包含本次发布所声明的功能。
3. macOS 原生分发包运行 `bash scripts/package-release.sh`。Windows 安装包在 Windows 开发机或现有 Windows 构建工作流中构建。产物仍须在对应平台安装验收。
4. 人工在本仓库创建对应标签的正式 Release（例如 `v0.3.0`），填写说明并上传已验证的安装包。不要勾选预发布；仅推送 Git 标签或上传 Actions Artifact 不会产生可用的 Release 安装包。
5. 用低版本应用手动检查，确认版本、说明和下载页面。没有上传匹配的平台安装包时，应用显示该平台暂不可用。

## 安装包命名

- macOS：`.dmg`，或文件名包含 `macOS`（不区分大小写）的 `.zip`。现有 `牛马上班-<版本>-macOS-universal.zip` 符合要求。
- Windows：`.exe` 或 `.msi`。
- 下载按钮打开本仓库 `/releases/tag/<标签>` 页面，用户选择适合自己的安装包。当前按操作系统筛选，不提供自动安装或芯片架构自动选择。

## 状态和边界

- 原生版本从应用包 Info.plist 读取；Tauri 版本从 Rust `AppHandle.package_info()` 读取；浏览器预览清单由 `npm run sync:frontend` 从 package.json 生成。
- 只接受三个数字段及可选的 `v` 标签前缀；草稿和预发布不会提示为正式更新。
- GitHub 不可达、返回限流或没有正式发布时，不会冒充“已是最新版”。公开接口不使用内置 Token。
- 自动检查开关及时间独立保存；手动检查不受自动检查的 24 小时间隔限制。
- 当前开发包采用临时签名。更新检测本身不代替 macOS Developer ID、公证或 Windows 分发验证。
